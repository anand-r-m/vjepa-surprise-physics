# G1' (c): provenance of the published ~98% (arXiv 2502.11831v1; read via alphaXiv full text)

| Question | Finding | Location |
|---|---|---|
| Is the 98% from RoPE models, not the public V-JEPA checkpoints? | The paper's V-JEPA models were pretrained by the authors "using RoPE ... instead of absolute positional embeddings" (all of B/L/H, all rows "positional embeddings Type RoPE, theta 10000"). The public V-JEPA checkpoints (original V-JEPA, vitl16/vith16) use absolute (sincos) positional embeddings (original V-JEPA paper, not re-read here). Hence the 98% is on a RoPE variant, not on the public vitl16.pth.tar. | Appendix A.3 ("We rely on the same training protocol as in the original V-JEPA paper, but use RoPE (Su et al., 2021) to encode positional information instead of absolute positional embeddings"); Table S1, row "positional embeddings / Type RoPE" |
| Is the paper's checkpoint released? | NOT found. The repo README (external/jepa-intuitive-physics/README.md) releases only raw surprises + performance.csv + eval code; it says "Every model starting with `vit` is a V-JEPA model" and gives no checkpoint link. The released config default_intphys.yaml names `vit_huge_rope` and a cluster-internal path `/checkpoint/garridoq/intphys/vit-h-rope/`. GitHub issues were not browsed (no web tool used), so issue numbers: not found. | README.md "Raw surprises and performance data"; configs/default_intphys.yaml |
| 98%: ViT-L or ViT-H? | "98% (95% CI [95%,99%])" is stated for the "flagship" V-JEPA = ViT-H ("the V-JEPA encoder ... ViT-Large, instead of ViT-H for the flagship model" is said for the per-property section; the 98% headline is in the section before it, evaluating "the flagship models proposed in the original works"; later "flagship V-JEPA architecture, using a ViT-Huge with pretraining on VideoMix2M"). The paper does not put the string "ViT-H" next to the 98% sentence itself, so the ViT-H attribution is by inference from "flagship" (not found as a literal statement). ViT-L numbers are reported separately (Fig. 2A, S7; HowTo100M, n=5). | Section "Representation prediction learns to detect violations of intuitive physics" (p.4); Section "Per property analysis of V-JEPA" (p.5); Fig. 1A |
| Aggregation behind the 98% | NOT stated for the headline number. Appendix A.8 (Table S3 text): "For IntPhys, we find that using the minimal surprise over all windows for each start frame [i.e. over context lengths] can be used" (the 'Filtered' variant). Main text p.6: "using the maximum surprise in a video, rather than the average, leads to better performance on single videos" (single-video setting, test set); Table S4 reports both Max and Avg pairwise error on the private test set (V-JEPA-H Avg is far better in pairwise: 0.28/0.0/0.09% vs Max 4.4/4.4/12.9% error). The pairwise dev numbers in the released performance.csv: "Relative Accuracy (avg)" and "(max)". Which one is the 98% is not stated; the released vit-h-rope-vm2m 'Filtered avg' mean over O1-O3 = (95.0+100.0+95.0)/3 = 96.67 (the "96.7%" ViT-H number); 'Filtered max' mean = 87.8. | Appendix A.8/Table S3 page 19; p.6; Table S4 p.22; released performance.csv |
| Frame skip | Stated: IntPhys V-JEPA frame skip 2, 7.5 fps, window size 16, window stride 2 (Table S3). Context length is chosen per property to maximise accuracy (p.4; App. B); with Filtered it is min over context lengths. | Table S3 (p.19); p.4 |
| ViT-L number | The released vit-l-rope-vm2m 'Filtered avg' = (85.0+91.67+91.67)/3 = 89.4 (the reference used in the spec); ViT-L HowTo100M Filtered avg = (91.67+88.33+90.0)/3 = 90.0. These are RoPE-ViT-L, not the public vitl16. Paper Table S4 (private test set) gives V-JEPA-L Avg pairwise error 1.4/3.1/2.0% (all), i.e. ~97-99% on test. | released performance.csv; Table S4 |

Conclusion: the 98% (flagship ViT-H, VideoMix2M, RoPE, frame skip 2) and the 96.7% ViT-H dev number cannot be attributed to the public V-JEPA vitl16 checkpoint; no RoPE checkpoint is released (not found). Expected public-checkpoint accuracy on dev is therefore a separate quantity (our stored M1 dev run: 73.3/83.3/85.0 per block, mean 80.6, filtered avg; see g1prime_a.md).
